### Corrections this state file adds

9. **The exit-window invariant was a tautology.** `entry_anchor_ts + offset < wct + feed_delay_s`
   reduces to `offset < 0`, because the anchor *is* `wct + feed_delay_s`. With the original
   three-line defect restored, the backtest ran clean — 178 trades, 30.9%, 0.03s minimum hold —
   and the guard never fired. `backtesting.md` claimed it was "verified to fire when the bug is
   reintroduced." It was not. Replaced with input-side checks and confirmed to raise.

10. **The fee function disagreed with Kalshi's published table** on three of five taker rows
    ($0.50 → $1.76, $0.20 → $1.13, $0.10 → $0.64) because of float64 error before `ceil`. Both
    implementations had it, and main's `CLAUDE.md` had recorded $1.76 as correct. Now `Decimal`,
    asserted in `tests/test_fees.py`.

11. **`orders.go::kalshiFee` does not exist.** Main's `CLAUDE.md` cited it as the Go half of a
    "once per language" pair. `orders.go::calcNetPnL` returns gross P&L with no fee deduction.
    There is no Go fee implementation and therefore no Go/Python fee parity risk.

12. **The backtest was stricter than training, not looser.** It skipped rows on the stored
    `is_blowout` / `is_garbage_time` columns, which use a 20-pt margin against the gate's 30.
    Removed when the traded-regime filter went in; per `feature-engineering.md:71-74` those
    columns discard 28,627 rows the system would really trade.

daily compute limit is a real constraint. **Expect the warehouse joint counts to fall by
roughly the same proportion**, i.e. ~5.5% → ~4.7% coverage. That is an inference from the cache,
not a measurement. Measure it properly during the Level 3 cache re-export, when a bounded
