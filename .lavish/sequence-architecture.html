Architecture proposal · Phase 6 · not yet implemented

The model sees a photograph. The market moves like a film.

Every live inference call collapses ~120 seconds of order-book flow and an ordered burst of NBA events into a single 58-number vector. This document measures exactly what that costs, proposes a dual-stream recurrent encoder to replace the collapse, and works through the full math of one training iteration with verified numbers.

Current: MMoEModel, 58→48 dense, ~37K params Proposed: dual-stream Δt-GRU + MMoE tower, 67,081 params Evidence: 8 recorded live runs, 4,597 inference calls, 77,005 ticks

02

Four blind spots, each with a number attached

"Add a price velocity field" was the right instinct and it is already there — four of them, in fact (d_yes_bid, d_spread, bid_velocity_30s, bid_acceleration_30s). Here is why that is not enough.

Blind spot 1 · measured on real ticks

Path shape is destroyed. Total variation is 2.5×–3.9× the net move.

I bucketed a real game's tick stream into windows the size of our actual event gaps and compared the net endpoint move against the full path length:

WindowMean net moveRange beyond netPath length beyond netPath / net
9 s (median gap)0.91¢0.46¢1.41¢2.55×
18 s1.20¢0.69¢2.80¢3.33×
27 s (p90 gap)1.42¢0.85¢4.05¢3.86×

At the p90 gap, the book traverses 4.05¢ of price path to produce a 1.42¢ net move. The model sees only the 1.42¢. A monotone 48→50 drift on thin volume and a violent 48→53→46→50 round trip on heavy volume produce an identical feature vector. Those are opposite trades: the first is a market that has already repriced, the second is a market fighting itself and about to hand us a maker fill.

Method: data/raw/kalshi_ticks/2026-03-23/KXNBASPREAD-26MAR23HOUCHI-CHI1.parquet, 5,539 ticks, 150 min. Path length = Σ|Δbid| within each window.

Blind spot 2 · verified across all 8 runs

d_yes_bid is identically zero on 45.8% of live inference calls.

ring_buffer.go:108 computes d_yes_bid as "bid now minus bid at the previous Snapshot()". But the NBA CDN returns a batch of new events per 3-second poll, and the engine fires one inference call per event, back to back, microseconds apart. The second call's "previous snapshot" is the first call's snapshot — same tick, same price.

// Across all 8 recorded runs, 4,583 consecutive call pairs: burst pairs (Δt < 0.5s): 2098 yes_bid unchanged: 2098 (100.0%) spaced pairs (Δt ≥ 0.5s): 2485 yes_bid unchanged: 1262 ( 50.8%) // Share of all live inference calls that are burst-adjacent: 45.8%

100.0%, not 99%. It is structural, not statistical. d_spread and bid_acceleration_30s degenerate the same way, since prevSnap and prevVelocity both update on every call (ring_buffer.go:146-147). Three of our four price-velocity features carry no information on nearly half of all live decisions — and the model has no way to know which half it is in, because Δt is not an input.

Blind spot 3 · grep the feature list

Elapsed wall-clock time is not a feature anywhere.

ALL_FEATURE_COLS has 58 entries. time_leverage is game clock. poss_since_timeout is a possession count. time_since_last_trade_ms is about the book, not about us. Nothing tells the model how long it has been since the last time it was asked. Every difference feature is therefore a rate with an unknown, wildly varying denominator ranging from 0 seconds to 1,008 seconds.

Blind spot 4 · 137 of 585 events

The event sequence is thrown away, and the thesis depends on it.

The core edge is "we notice lineup changes before the market does." Substitutions are 23% of all live events (137 of 585 in the sampled game). The model receives was_sub, sub_count_edge and lineup_changed_edge — flags and counters. It never receives the ordering: sub → sub → timeout → 3pt make → 3pt make is a coach reacting and it working. The same five events shuffled mean nothing. A bag of counters cannot represent that distinction; a sequence model represents it natively.

The pattern. Every one of these is the same failure: we chose the summary statistic in advance, at a window size we guessed, on a clock we did not measure. A recurrent encoder does not fix any single feature — it removes the requirement that we guess correctly and lets the loss pick the window.

Proposed architecture

Two encoders, one fusion point, and the existing MMoE tower kept intact above it. The heads, the gates, the entropy regularizer, the masked loss, the exit simulator targets, and the whole Go execution path all stay exactly as they are.

Market stream

1 Hz grid, 120 steps, 8 channels

Resample the ring buffer onto a regular one-second grid rather than feeding raw ticks. This makes Δt constant so a plain GRU is correct, and it makes the tensor shape fixed so the Go side can ship a dense array with no padding logic.

Channels: yes_bid, yes_ask, spread, mid, yes_last, log1p(traded_size), Δopen_interest, bid−last. All prices as deviations from the bid at t=0 of the window, so the encoder learns shape rather than level; the absolute level enters once, via the static path.

Cost: Go must maintain a 1 Hz resample. Payload grows from 14 floats to 960 (~4 KB). At a 9s median arrival gap this is free.

Event stream

Last 32 events, Δt-aware GRU

K = 32 events ≈ 5 minutes of game at the observed 9s median — which is exactly the 3–5 minute scoring-run window the whole thesis targets. Each step carries the 33 consolidated physics features, an 8-dim learned embedding of action_type, and both elapsed times: Δtwall (seconds since previous event) and Δtgame (game-clock seconds).

The cell decays its own memory by elapsed wall time (§5). This is what makes the burst problem disappear: on a 0-second gap the previous state passes through untouched, and on a 1,008-second timeout it is erased.

Cost: 32 sequential GRU steps per inference. At hidden 64 this is ~200 μs on CPU, against a 3 ms current p95.

Two decisions that matter more than the cell type

Windowed re-encode

Recommended

Every inference call re-runs the GRU over the last 32 events from a zero initial state. The model is a pure function of its window.

Why this and not a persistent hidden state: the NBA feed replays a backfill burst at startup (nba_feed.go:161) and drops events when the channel is full (nba_feed.go:148). A stateful RNN would absorb both into a hidden vector that is silently wrong for the rest of the game, with no way to detect it. Re-encoding is idempotent, replay-safe, and makes the backtest bit-identical to live.

Cost: 32× redundant compute per call. Absolute cost ~200 μs. Buys: the single property this system needs most.

Persistent hidden state

Rejected

Carry h across the whole game, one GRU step per event. Unbounded memory, 32× cheaper.

Rejected on robustness, not cost. It introduces a hidden, unobservable, unrecoverable divergence between backtest and live the first time an event is dropped or replayed — the exact class of bug that CLAUDE.md tells us to be paranoid about.

Reconsider if: we ever move to a gap-free push feed (Sportradar WS) and add a state checksum.

GRU

Pick

3 gates, ~25% fewer params than LSTM at equal hidden size. At 24K joint rows, parameters are the binding constraint.

LSTM

No

4 gates and a separate cell state. No evidence it wins at sequence length 32–120; costs ~33% more parameters we cannot afford.

Transformer

Not yet

Wants 10–100× our joint data. Revisit after a full season of tick recording, when Head B has 200K+ rows.

04

The math for one training iteration

Batch size B = 256. Every number in the numeric trace below was computed with PyTorch autograd and is reproduced verbatim.

Shapes

X_E ∈ ℝ^(B × 32 × 43) event stream 43 = 33 physics + 8 type-embed + Δt_wall + Δt_game X_M ∈ ℝ^(B × 120 × 8) market stream 8 channels on a 1 Hz grid X_S ∈ ℝ^(B × 11) static pregame block, unchanged Δ ∈ ℝ^(B × 32) elapsed wall seconds per event step targets: y_A ∈ ℝ^B (binary) y_B ∈ ℝ^(B×10) (logit deltas) y_C ∈ ℝ^(B×10) (binary) masks: m_run ∈ {0,1}^B m_mkt ∈ {0,1}^B

Step 1 — the Δt-gated GRU cell

The standard GRU, with one addition. Before the cell reads the previous hidden state, that state is decayed by the elapsed time since the previous event, at a rate learned per hidden unit:

λ = softplus(τ) τ ∈ ℝ^64 learned, softplus keeps λ > 0 h'ₜ₋₁ = hₜ₋₁ ⊙ exp(−Δtₜ · λ) ← the entire fix for blind spots 2 and 3 rₜ = σ(W_r xₜ + U_r h'ₜ₋₁ + b_r) reset gate zₜ = σ(W_z xₜ + U_z h'ₜ₋₁ + b_z) update gate nₜ = tanh(W_n xₜ + rₜ ⊙ (U_n h'ₜ₋₁) + b_n) candidate hₜ = (1 − zₜ) ⊙ nₜ + zₜ ⊙ h'ₜ₋₁ note: h', not h

Each hidden unit gets its own λ, so the network can hold one unit with λ ≈ 0 (season-long context, survives a timeout) and another with λ ≈ 1 (this-possession context, erased by any real gap). We no longer choose the window — the loss does, per unit.

Step 2 — forward, with real numbers

A 2-unit cell over 2 steps, so every quantity is inspectable. Inputs x₁=[1.0, 0.0] at Δt=1s and x₂=[2.0, 1.0] at Δt=4s. Initial h₀ = [0, 0], τ = [0.20, 0.60] so λ = softplus(τ) = [0.7981, 1.0375].

─── t = 1 ─── Δt = 1s, h₀ = [0, 0] h'₀ = [0, 0] ⊙ exp(−1·λ) = [0.000000, 0.000000] r₁ = σ(W_r x₁) = [0.622459, 0.524979] z₁ = σ(W_z x₁) = [0.425557, 0.549834] n₁ = tanh(W_n x₁) = [0.664037, -0.379949] h₁ = (1−z₁)⊙n₁ + z₁⊙h'₀ = [0.381451, -0.171040] ─── t = 2 ─── Δt = 4s ← a real gap, the market moved without us h'₁ = h₁ ⊙ exp(−4·λ) = [0.015665, -0.002696] exp(−4·0.7981)=0.04106 → unit 0 retains 4.1% of its memory exp(−4·1.0375)=0.01576 → unit 1 retains 1.6% of its memory r₂ = σ(W_r x₂ + U_r h'₁) = [0.690979, 0.645174] z₂ = σ(W_z x₂ + U_z h'₁) = [0.500257, 0.474819] n₂ = tanh(W_n x₂ + r₂⊙(U_n h'₁)) = [0.935702, -0.096838] h₂ = (1−z₂)⊙n₂ + z₂⊙h'₁ = [0.475447, -0.052138]
Read the highlighted line. A four-second gap erased 96% and 98% of the two units' memory. The current architecture has no equivalent operation — it would have treated a 4-second gap and a 400-second gap as the same event boundary, because it was never told which one happened.

Step 3 — the null-market gate

77K of our 101K training rows are basketball-only: real possessions from games recorded before the Kalshi feed existed, with no ticks at all. They must still train Heads A and C. The market encoder output is therefore switched, not zeroed:

m* = m_mkt ⊙ GRU_M(X_M)[−1] + (1 − m_mkt) ⊙ m_null m_null ∈ ℝ³² learned z = concat(e, m*, s) ∈ ℝ¹⁰⁷ 64 + 32 + 11

A learned constant rather than a zero vector, because zero is a real point in the market embedding space that some genuine order-book states will map to. Gradient from basketball-only rows flows into m_null and stops there — it never touches GRU_M, so 77K rows of tickless data cannot teach the market encoder anything false.

Step 4 — experts, gates, heads (unchanged from today)

Eᵢ(z) = Dropout(ReLU(BN(W₂ᵢ · Dropout(ReLU(BN(W₁ᵢ z)))))) i = 1..3, Eᵢ(z) ∈ ℝ⁶⁴ g_h(z) = softmax(W_h z) ∈ ℝ³ h ∈ {A, B, C} u_h = Σᵢ g_h(z)ᵢ · Eᵢ(z) ∈ ℝ⁶⁴ â = σ(HeadA(u_A)) ∈ ℝ¹ b̂ = HeadB(u_B) ∈ ℝ¹⁰ ĉ = σ(HeadC(u_C)) ∈ ℝ¹⁰

Step 5 — the masked multi-task loss

Identical to trainer.py::_compute_loss today. Nothing about the sequence encoders changes the objective:

s_traj = 𝟙[ mean|y_B| > 0.02 ] drop near-flat trajectories M_B = m_mkt ⊙ s_traj ℒ_A = BCE(â, y_A ; mask = m_run) ℒ_B = Huber_{β=1}(b̂, y_B ; mask = M_B) ℒ_C = BCE(ĉ, y_C ; mask = m_run) H = Σ_h −Σⱼ g_h(z)ⱼ log g_h(z)ⱼ gate entropy, prevents expert collapse ℒ = w_A ℒ_A + w_B ℒ_B + w_C ℒ_C − λ_H · H w = (1.0, 1.0, 0.3), λ_H = 0.02

Concretely, for the trace above with a Head B target of +5¢ from 50¢:

ŷ = w_out · h₂ + b_out = (1.0)(0.475447) + (−1.0)(−0.052138) = 0.527585 y = logit(0.55) − logit(0.50) = 0.182300 δ = ŷ − y = 0.345285 ℒ_B = ½δ² (since |δ| ≤ β = 1) = 0.059611

Step 6 — backward: BPTT through the decay

The gradient reaches step t from two directions: the loss at the top, and every later timestep through the recurrence. The Jacobian of the recurrence now carries the decay factor:

∂ℒ/∂hₜ = [direct] + (∂hₜ₊₁/∂hₜ)ᵀ · ∂ℒ/∂hₜ₊₁ ∂hₜ₊₁/∂hₜ = diag(exp(−Δtₜ₊₁·λ)) · [ diag(zₜ₊₁) + (1−zₜ₊₁) ⊙ ∂nₜ₊₁/∂h'ₜ + (nₜ₊₁ − h'ₜ) ⊙ ∂zₜ₊₁/∂h'ₜ ] // and τ picks up gradient from every timestep it gated: ∂ℒ/∂τ = Σₜ σ'(τ) ⊙ (−Δtₜ) ⊙ hₜ₋₁ ⊙ exp(−Δtₜ·λ) ⊙ ∂ℒ/∂h'ₜ₋₁

Note the shape of the τ gradient: it scales with Δtₜ. Long gaps dominate the learning signal for the decay rates, which is the correct behavior — timeouts and quarter breaks are precisely the events that should teach the model what to forget.

Autograd on the trace above, verbatim:

∂ℒ/∂W_z = [[−0.159724, −0.079419], [−0.016501, −0.008106]] ∂ℒ/∂W_n = [[ 0.044707, 0.021476], [−0.360460, −0.179637]] ∂ℒ/∂W_r = [[ 0.000031, 0.000016], [−0.000364, −0.000182]] ← tiny: reset gate barely matters when h' ∂ℒ/∂U_r = [[ 0.00000024, −0.00000004], [−0.0000029, 0.0000005]] is already decayed ∂ℒ/∂τ = [−0.004583, −0.001361] ← negative ⇒ push λ down ⇒ ∂ℒ/∂w_out = [ 0.164165, −0.018002] remember longer
The recurrent weights get almost no gradient here, and that is the lesson. ∂ℒ/∂U_r is ~10⁻⁷ while ∂ℒ/∂W_n is ~10⁻¹ — a factor of a million. The 4-second gap decayed h'₁ to near zero, so the recurrent path had almost nothing to propagate. With sparse, bursty NBA events this will be the common case, and it is the concrete argument for keeping the event GRU small (hidden 64, not 256): most of its recurrent capacity will sit idle across long gaps.

Step 7 — AdamW update

mₖ = β₁mₖ₋₁ + (1−β₁)g vₖ = β₂vₖ₋₁ + (1−β₂)g² β₁=0.9, β₂=0.999 m̂ = mₖ/(1−β₁ᵏ) v̂ = vₖ/(1−β₂ᵏ) θ ← θ − lr·( m̂/(√v̂ + ε) + wd·θ ) lr = 1e-3, wd = 1e-4 // At k=1 the bias correction makes the step ≈ −lr·sign(g), independent of |g|: Δw_out = [−0.00100000, +0.00099999] ≈ −lr·sign(g) ✓ Δτ = [+0.00099999, +0.00099999] both λ pushed up ⇒ forget faster then: clip_grad_norm_(1.0) → optimizer.step() → ReduceLROnPlateau on val loss

05

The central risk, and the asset that offsets it

The risk

1.8× the parameters on the same 24K joint rows

37,000 → 67,081 parameters, which halves data-per-parameter from 2.7 to 1.5. Head B — the head that actually drives entry — sees roughly 13,900 usable rows from 148 games recorded over three weeks. That is 5.8 samples per parameter in the market path. A sequence model with too little data will happily memorize the shape of one March market regime and look excellent in validation.

The existing splits already discourage this: joint rows split chronologically at HEADB_SPLIT_DATE (dataset.py:821), so validation is genuinely future data. But three weeks is a short future.

The offset — this is the strongest reason to do it

77,005 unlabeled ticks are already on disk

The market encoder does not need possession labels. It only needs tick sequences — and we have 77,005 of them across 52 recorded market files that were never usable by the current architecture, because a dense vector has nothing to pretrain.

Pretrain GRU_M self-supervised on next-second prediction: given seconds t−119..t, predict Δbid at t+1..t+5. Then freeze or fine-tune it inside the full model. This turns 24K labeled rows into 24K labeled rows plus 77K unlabeled steps of representation learning.

This asset only exists in the sequence formulation. The current model cannot consume an unlabeled tick stream at all.

Non-negotiable gate before this replaces anything. The current model backtests at 207 trades / 47.8% win / +$37,409 net. The sequence model ships only if it beats that on the same backtest harness with the same entry gates, and only after /validate-features passes on the new stream builders. The 2024-26 test set stays untouched either way.

07

Failure modes I have not solved

Backtest / live divergence

The market stream is built by Go live and by pandas in training. Today that parity risk covers 14 numbers; it would cover 960. The resample rule (forward-fill? last-tick-in-second? gap handling?) must be specified once and tested against both implementations, or we reintroduce the exact bug class that the Phase 1 aggregator post-mortem already caught once.

Feed delay is baked into targets

Training joins ticks at wall_clock_ts + 20s (dataset.py:659) to simulate CDN lag. A 120-second market window that ends 20 seconds before the event we are reacting to is not the window live sees. I believe the window should end at join time, not event time, but this needs a deliberate decision.

Cold start

The first 32 events of a game have no full window, and the first 120 seconds have no full tick history. Zero-padding plus a validity mask channel is the obvious answer, but early Q1 is also when the market is thinnest and least efficient — possibly our best window. Worth measuring rather than assuming.

Market swaps mid-window

The scanner swaps strike tickers (market_scanner.go) and the engine already discards stale-ticker ticks (game.go:180). A 120-second window that straddles a swap contains two different contracts' prices. The window needs to be invalidated or re-based on swap, and neither is currently implemented.
